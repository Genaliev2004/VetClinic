# Этап 6. План и результаты тестирования

## 6.1. Цели и объекты тестирования

Нужно проверить четыре вещи:

1. база данных в обеих СУБД соблюдает все бизнес-правила BR-01…BR-23;
2. приложение одинаково работает с PostgreSQL и Microsoft SQL Server;
3. приложение разворачивается и работает в двух ОС: Windows 11 и Ubuntu Linux;
4. стороннее лицо (одногруппник) может развернуть проект только по README.

## 6.2. Уровни тестирования

| Уровень | Что проверяется | Средство | Где лежит |
|---------|-----------------|----------|-----------|
| 1. Тесты ограничений БД | CHECK, UNIQUE, FK, уникальные индексы с условием, триггеры, каскад | SQL-скрипты (PL/pgSQL, T-SQL), каждая проверка откатывается | `sql/*/03_constraint_tests.sql` |
| 2. Модульные (unit) | чтение настроек и выбор файла ОС, проверка ввода, слоты, счёт, перевод ошибок СУБД | JUnit 5, без БД | `app/src/test/java/.../config`, `service`, `db` |
| 3. Интеграционные | DAO, SQL-запросы, транзакции, ограничения через JDBC — **одинаковый набор на каждой СУБД** | JUnit 5 + реальная БД, транзакция теста откатывается | `app/src/test/java/.../integration` |
| 4. Системные (ручные) | сценарии пользователя в графическом интерфейсе | чек-лист ниже | — |
| 5. Кросс-платформенные | сборка, тесты и запуск в Windows и Linux | скрипты `scripts/*.bat`, `scripts/*.sh` | раздел 6.6 |
| 6. Приёмочное (одногруппник) | развёртывание по README без помощи автора | протокол | `docs/06_peer_testing.md` |

## 6.3. Тесты ограничений БД (уровень 1)

34 теста (T01–T34). Номера и содержание в PostgreSQL и SQL Server одинаковые.
Каждый тест пытается нарушить одно правило и ожидает ошибку. Три теста
(T07, T22, T34), наоборот, проверяют, что допустимые данные принимаются.

| Тест | Правило | Тест | Правило |
|------|---------|------|---------|
| T01–T02 | BR-01 обязательные ФИО | T17–T19 | BR-11 слот 08:00–19:30, статус |
| T03–T04 | BR-02 формат и уникальность телефона | T20–T22 | BR-12/13 занятость врача и питомца, отменённый слот свободен |
| T05–T07 | BR-03 e-mail | T23 | BR-14 диагноз у проведённого приёма |
| T08–T09 | BR-04/05 владелец, пол | T24 | BR-15 уволенный врач (триггер) |
| T10–T11 | BR-06/07 дата рождения, вес | T25–T26 | BR-16 конечные статусы (триггер) |
| T12–T13 | BR-08 чип | T27–T29 | BR-17 услуги и отмена (триггеры) |
| T14–T15 | BR-09/10 справочники, цена | T30–T31 | BR-18/19 количество, повтор услуги |
| T16 | BR-23 дата приёма на работу | T32–T34 | BR-20/21 запрет удаления, каскад |

**Результат (19.10.2026):**

| СУБД | PASS | FAIL |
|------|------|------|
| PostgreSQL 18.6 (Windows 11) | 34 | 0 |
| Microsoft SQL Server 2022 16.0.1000.6 (Windows 11) | 34 | 0 |

После прогона количество строк в таблицах не изменилось (10 владельцев,
22 приёма, 26 строк услуг).

## 6.4. Модульные и интеграционные тесты (уровни 2–3)

Запуск: `scripts\build.bat test` (Windows) или `bash scripts/build.sh test` (Linux).
Набор СУБД задаётся параметром `-Dtest.databases=postgresql,mssql`. Если СУБД
недоступна, её тесты пропускаются (`Skipped`), а не падают.

| Класс | Тестов | Что проверяет |
|-------|--------|---------------|
| `AppConfigTest` | 8 | определение ОС; порядок файлов: ОС → db.properties → local.properties → -D; CRLF/LF; `${user.home}`; пароль скрыт в описании подключения |
| `ValidatorTest` | 18 | нормализация телефона (`8 (903) 111-22-33` → `+79031112233`), e-mail, чип, вес, цена, даты, количество |
| `SlotCalculatorTest` | 5 | 24 слота в дне, границы, занятые слоты, «сегодня» — только будущие, прошлый день — пусто |
| `InvoiceFormatterTest` | 4 | итог счёта, формат денег, разделитель строк Windows/Linux |
| `DialectTest` | 8 | перевод ошибок PostgreSQL и SQL Server: триггеры, UNIQUE, индекс с условием, FK при вставке и удалении, ошибки входа |
| `ClinicServiceValidationTest` | 5 | запись в прошлое, вне слота, неверный телефон, дата рождения в будущем, период отчёта |
| `PostgresIntegrationTest` | 24 | см. ниже — на PostgreSQL |
| `MssqlIntegrationTest` | 24 | те же 24 теста — на SQL Server |

Интеграционные тесты (`AbstractIntegrationTest`) проверяют: CRUD справочника;
выдачу id через IDENTITY; поиск владельцев; сообщения об ошибках уникальности и FK;
несколько питомцев без чипа (фильтрованный индекс в SQL Server); чтение
CHAR/DECIMAL/DATE; конфликт записи к врачу; освобождение отменённого слота;
триггер уволенного врача; слот вне рабочего времени; расписание и историю;
проведение приёма с ценами из прайса; сохранение исторической цены при смене
прайса; неактивную услугу; диагноз при завершении; запрет отмены приёма с
услугами; отмену только запланированного; окончательность статуса; каскадное
удаление; оба отчёта. Отдельный тест проверяет **атомарность транзакции**
`ClinicService.saveVisit`: если вторая услуга отклонена триггером, не сохраняются
ни диагноз, ни первая услуга, ни смена статуса.

**Результат (19.10.2026, Windows 11, Java 25.0.2, Maven 3.9.15):**

```

  AppConfigTest 8, DialectTest 8, ValidatorTest 18, SlotCalculatorTest 5,
  InvoiceFormatterTest 4, ClinicServiceValidationTest 5,
  PostgreSQL 24, Microsoft SQL Server 24
BUILD SUCCESS
```

## 6.5. Ручные системные тесты (уровень 4)

Выполняются в собранном приложении на тестовых данных. Каждый сценарий
проверяется на обеих СУБД: в окне входа выбирается другая СУБД, и сценарий
повторяется.

| № | Роль | Сценарий | Ожидаемый результат |
|---|------|----------|---------------------|
| M01 | — | Запуск `run.bat`/`run.sh`, выбор СУБД, «Подключиться» | В строке состояния версия сервера, кнопка «Войти» активна |
| M02 | — | В `db.properties` указать неверный пароль, перезапустить | Сообщение «Нет подключения к базе данных…», программа не падает |
| M03 | Администратор | Добавить вид «Черепаха», затем добавить «Кошка» | Первый добавлен; на второй — «Такой вид животного уже есть.» |
| M04 | Администратор | Удалить вид «Кошка» | «Нельзя удалить вид: есть питомцы этого вида.» |
| M05 | Администратор | Изменить цену «Первичный осмотр» на 1300 | Цена в прайсе изменилась, суммы старых счетов прежние |
| M06 | Администратор | Уволить врача, открыть запись на приём | Врача нет в списке для записи |
| M07 | Администратор | Отчёты за 01.01.2026–31.12.2026 | 7 врачей, итог 30 550,00 ₽ (на исходных данных) |
| M08 | Регистратор | Новый владелец с телефоном `8 (999) 123-45-67` | Сохранён как `+79991234567` |
| M09 | Регистратор | Новый владелец с телефоном уже существующего | «Владелец с таким телефоном уже зарегистрирован.» |
| M10 | Регистратор | Питомец с датой рождения в будущем / чипом из 10 цифр | Сообщения проверки, запись не создаётся |
| M11 | Регистратор | Записать питомца: врач Соколова, 21.10.2026 | В списке времени нет 10:00 и 10:30 (заняты) |
| M12 | Регистратор | Отменить запись, затем записать на тот же слот | Слот снова свободен, запись создаётся |
| M13 | Врач | Провести приём: услуги, без диагноза → «Завершить приём» | «Чтобы завершить приём, укажите диагноз.» |
| M14 | Врач | Указать диагноз → «Завершить приём» | Статус «Проведён», сумма в расписании |
| M15 | Регистратор | Счёт по проведённому приёму → «Сохранить в файл» | Файл в «Документах» (Windows, CRLF) / домашнем каталоге (Linux, LF) |
| M16 | Регистратор | Отменить проведённый приём | «Отменить можно только запланированный приём.» |

Все окна приложения на обеих СУБД отрисованы утилитой

## 6.7. Найденные и исправленные дефекты

| № | Дефект | Причина | Исправление |
|---|--------|---------|-------------|
| D1 | Тестовый скрипт PostgreSQL не выполнялся | вложенная строка `$c$$q$` содержала `$$` и закрывала внешний блок `DO $$` | внешний блок получил метку `$tests$` |
| D2 | `mvnw.cmd` не запускал Maven, если в пути к профилю пользователя есть пробел | путь к `mvn.cmd` не был в кавычках | путь взят в кавычки |
| D3 | `scripts\build.bat` выдавал «mvnw.cmd не является командой» в папке с кириллицей | особенность cmd.exe при `call mvnw.cmd` | вызов `call .\mvnw.cmd` |
| D4 | Тесты Maven падали при запуске JVM | путь `-Djava.library.path` с пробелами без кавычек | кавычки в `argLine` |
| D5 | Кнопки «◀ ▶» отображались квадратами | в шрифте Segoe UI нет этих символов | заменены на `<` и `>` |
| D6 | Проверка T26 из первой версии давала PASS по чужой причине | для отмены был взят проведённый приём, и срабатывало правило BR-16, а не BR-17 | для проверки BR-17 взят запланированный приём с предварительно добавленной услугой |
| D7 | Тесты могли не запуститься на Java 17 (Ubuntu) | в `argLine` был флаг `--enable-native-access`, нужный только Java 22+ | флаг убран: без него лишь выводится предупреждение |
| D8 | `maven-wrapper.properties` попал в репозиторий с окончаниями CRLF | файл добавлен до появления `.gitattributes` | окончания строк нормализованы (`git add --renormalize`) |
| D9 | `apt` на Ubuntu с закончившейся поддержкой отвечает 404 | пакеты переезжают на old-releases.ubuntu.com | `setup_ubuntu.sh` сам переключает источники; JDK 21 с запасным вариантом JDK 17 |
