# Этап 1. Описание предметной области

## 1.1. Общее описание

Ветеринарная клиника принимает домашних животных (питомцев). У каждого питомца
есть ровно один владелец, у владельца может быть несколько питомцев. Питомец
относится к одному виду животных (кошка, собака, птица, …); порода хранится
как свободный текст, потому что для многих видов (птицы, грызуны) единого
справочника пород нет.

В клинике работают врачи. У врача одна основная специализация (терапевт,
хирург, дерматолог, …). Уволенный врач не удаляется из базы — у него
сохраняется история приёмов, он просто помечается как неактивный.

Клиника оказывает платные услуги (осмотр, вакцинация, УЗИ, анализы, операции…).
У услуги есть текущая цена прайса, которую администратор может изменять.
Услуги, которые больше не оказываются, помечаются как неактивные.

Регистратор записывает питомца на **приём** к врачу на конкретные дату и время.
Приёмы идут слотами по 30 минут с 08:00 до 20:00 (последний слот — 19:30).
Приём может быть в одном из трёх состояний:

* `SCHEDULED` — запланирован;
* `DONE` — проведён (врач внёс диагноз и оказанные услуги);
* `CANCELLED` — отменён.

На одном приёме может быть оказано несколько услуг, одна услуга оказывается на
многих приёмах (связь «многие-ко-многим»). Для каждой оказанной услуги
хранится количество и **цена на момент оказания** — после изменения прайса
сумма старых счетов не меняется. Сумма счёта за приём = Σ(цена × количество).

## 1.2. Бизнес-правила и ограничения

| Код | Правило | Где реализовано |
|-----|---------|-----------------|
| BR-01 | Фамилия, имя владельца и врача обязательны; отчество необязательно | NOT NULL |
| BR-02 | Телефон владельца и врача обязателен, уникален, формат `+7XXXXXXXXXX` | UNIQUE + CHECK |
| BR-03 | E-mail владельца необязателен, но если указан — уникален и похож на адрес | уникальный индекс с условием + CHECK |
| BR-04 | У питомца ровно один владелец и один вид | FK NOT NULL |
| BR-05 | Пол питомца — `M` (самец) или `F` (самка) | CHECK |
| BR-06 | Дата рождения питомца не может быть в будущем и раньше 1980 г. | CHECK |
| BR-07 | Вес питомца, если указан, — от 0 до 1000 кг (не включая 0) | CHECK |
| BR-08 | Номер чипа необязателен, если указан — 15 цифр и уникален | CHECK + уникальный индекс с условием |
| BR-09 | Названия видов, специализаций, услуг уникальны | UNIQUE |
| BR-10 | Цена услуги ≥ 0 | CHECK |
| BR-11 | Приём начинается в 08:00–19:30, ровно в :00 или :30 | CHECK |
| BR-12 | У врача не может быть двух неотменённых приёмов на одно время | уникальный индекс с условием |
| BR-13 | У питомца не может быть двух неотменённых приёмов на одно время | уникальный индекс с условием |
| BR-14 | Проведённый приём обязательно содержит диагноз | CHECK |
| BR-15 | Нельзя записать на приём к неактивному (уволенному) врачу | триггер |
| BR-16 | Приём в статусе `DONE` или `CANCELLED` нельзя вернуть в другой статус | триггер |
| BR-17 | Услугу нельзя добавить к отменённому приёму; нельзя добавить неактивную услугу; нельзя отменить приём, по которому уже оказаны услуги | триггеры |
| BR-18 | Количество услуги в приёме — от 1 до 100; цена ≥ 0 | CHECK |
| BR-19 | Одна и та же услуга в приёме указывается один раз (количество — отдельным полем) | PRIMARY KEY |
| BR-20 | Нельзя удалить владельца с питомцами, питомца с приёмами, вид/специализацию/врача/услугу, на которые есть ссылки | FK (NO ACTION) |
| BR-21 | При удалении приёма удаляются и его строки услуг | FK ON DELETE CASCADE |
| BR-22 | Дата приёма при создании новой записи — не в прошлом | приложение |
| BR-23 | Дата приёма на работу врача не в будущем | CHECK |

## 1.3. Что должно делать приложение

При запуске пользователь выбирает роль и видит только нужные ему вкладки.

**Администратор**

1. Справочник видов животных: просмотр, добавление, изменение, удаление.
2. Справочник специализаций: то же.
3. Врачи: добавление, изменение, пометка «уволен / работает».
4. Услуги: добавление, изменение цены, пометка «не оказывается».
5. Отчёты: выручка по врачам за период; топ услуг за период.

**Регистратор**

1. Владельцы: поиск по фамилии/телефону, добавление, изменение, удаление.
2. Питомцы владельца: добавление, изменение, удаление; история приёмов питомца.
3. Расписание: просмотр приёмов на выбранную дату (по всем врачам или по одному),
   поиск свободных слотов врача, запись питомца, отмена записи.
4. Счёт по проведённому приёму (список услуг, итоговая сумма).

**Врач**

1. Список своих приёмов на дату.
2. Проведение приёма: ввод диагноза, добавление/удаление оказанных услуг,
   завершение приёма (статус `DONE`) — всё в одной транзакции.

**Общие требования**

* Работа с PostgreSQL и Microsoft SQL Server; выбор СУБД и параметры
  подключения — в файле `config/db.properties`.
* Настройки, зависящие от ОС (шрифт интерфейса, внешний вид, путь к нативной
  библиотеке Windows-аутентификации SQL Server), — в файлах
  `config/os/windows.properties` и `config/os/linux.properties`.
* Доступ к БД только через JDBC (`PreparedStatement`, транзакции), без ORM и
  фреймворков.
* Ошибки ограничений БД показываются пользователю понятным сообщением на
  русском языке.
